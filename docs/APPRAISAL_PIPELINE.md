# 鑑定流程設計（市集現場拍照 → 買/不買判斷）

**寫給未來的自己：** 這份記錄 Sam × Claude session 討論出來的**端到端理想流程**，以及**目前做到哪、下一步做什麼**。方便隔幾週回頭看時能快速對齊。

---

## 情境設定

**Sam 在關西市集（下午 3 點）：**
- 看到一只錶／一個花瓶／一輛老車
- 賣家開價 ¥3,000
- 想在 30 秒內判斷：**這是撿漏還是被坑？值不值得砍價？是不是仿品？**
- 手機 4G 連線（可能不穩）
- 想邊看邊做決策

**核心產出（給使用者的答案）：**
1. 一眼判斷：🟢 撿漏 / 🟡 合理 / 🔴 偏高 / ⚠️ 疑似仿品
2. 議價目標：「砍到 ¥X 值得買，否則 pass」
3. 議價依據：Yahoo/Mercari 過去 3 個月真實成交價（不只 AI 估算）
4. 仿品風險檢查點（品牌類物件）

## 部署架構決策

**選定：**
- **Backend**：Hetzner CX33 現有 VPS（跟其他個人專案共用）
  - 加 1 Docker container，~500 MB RAM
  - Playwright headless Chromium 另 ~500-800 MB（只在 Cron 跑時吃）
  - SQLite 檔在 VPS disk，rsync 定期備份到你 Mac
- **Frontend**：Cloudflare Pages（PWA static build 免費）
  - 或跟 backend 同機用 Nginx（省 DNS 一層）
- **Public 存取**：subdomain + Cloudflare tunnel（不用開 VPS 埠）
- **Auth**：單人用，簡易 API token 塞 header 即可

**為什麼不換 GEX（GPU）自 host VLM：**
- Qwen2-VL / LLaVA 品質已接近 Claude，但要 GPU
- Hetzner GEX GPU 專用機月費 ~€500+
- 你月呼叫量 <1000 次的情況下，付 Claude API 遠比自 host 便宜

## 每階段的 metric 追蹤

實作完後要追蹤：
- **鑑定平均延遲**（p50 / p95）→ 目標 <10s
- **Claude 呼叫成本**（¥/月）→ 觀察一個月看要不要優化
- **OCR 抽字命中率**（有多少張抽到有意義的字）
- **使用者 override 率**（AI 說「合理」使用者收藏了 → 說明使用者不信 AI）
